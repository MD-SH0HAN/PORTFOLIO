Engineering habits

  • Keep change small, reviewable, and traceable.
  • Automate repeatable work and test failure paths.
  • Keep configuration and secrets out of source control.
  • Make service health observable and actionable.

Infrastructure lifecycle

  • Declare configuration and initialize providers/backends.
  • Plan, review policy and cost, then approve.
  • Apply, verify outputs, inspect drift, and preserve state.
  • Use encrypted remote state, locking, and short-lived identity.

03 / ADVANCED PLATFORM ENGINEERING

Operate through declarative control loops.

Kubernetes architecture & operations

API server, etcd, scheduler, controllers, kubelet, container runtime, CNI, CSI, affinity, taints/tolerations, topology spread, HPA, PDB, admission policy, RBAC, and cluster upgrades.

Helm, Kustomize & GitOps

Render reusable charts and overlays. Argo CD and Flux compare Git-defined desired state with cluster state and reconcile drift. Validate generated manifests before apply.

Platform engineering

Internal developer platforms combine catalogs, templates, golden paths, documentation, ownership, and policy guardrails. Backstage can provide catalog and Scaffolder capabilities when integrated with an operating portal.

Cloud-native architecture

Microservices, service mesh, serverless, hybrid cloud, workload identity, scaling, failure domains, redundancy, RTO/RPO, backups, restore drills, and failover design.

Verification boundary. A manifest is not proof of runtime enforcement. Verify the target CNI for NetworkPolicy, Metrics API for autoscaling, identity bindings, storage classes, admission controls, and real rollout/recovery behaviour.

04 / OBSERVABILITY, RELIABILITY & SECURITY

Make service behaviour visible.

Operational quality depends on trustworthy signals, explicit objectives, disciplined response, secure delivery, and recovery that has been tested.

METRICS

Prometheus & monitoring

Scrape time series, query PromQL, and evaluate recording/alert rules. Use counters, gauges, histograms, bounded labels, and actionable alert thresholds.

DASHBOARDS & LOGS

Grafana & structured logging

Build question-driven dashboards with deployment markers and links to logs/traces. Centralized logs need structured fields, correlation IDs, access control, and retention.

TRACING

OpenTelemetry

APIs, SDKs, semantic conventions, and Collector pipelines generate and export telemetry. Context propagation connects work across service boundaries.

SRE

SLIs, SLOs & SLAs

Define eligible good events, indicators, target windows, and external commitments. Error budgets help balance delivery risk with reliability investment.

INCIDENTS

Incident management & learning

Detect, declare, assign roles, mitigate, communicate, recover, and learn. Maintain runbooks, timelines, escalation paths, blameless reviews, and owned corrective actions.

SECURE DELIVERY

DevSecOps & supply chain

SAST, SCA, secret scanning, IaC/container scanning, SBOMs, signing, provenance, policy checks, and patch response across the delivery lifecycle.

IDENTITY

IAM & secrets

Least privilege, scoped RBAC/IAM, OIDC federation, short-lived workload credentials, secret rotation, audit logs, and secure key management.

GOVERNANCE

Network security & policy

Segmentation, TLS, private endpoints, encryption, policy-as-code, asset inventory, audit evidence, and appropriate control baselines.

RECOVERY

Backup & disaster recovery

Define RPO/RTO, encrypt and isolate backups, test restoration, rehearse failover, and monitor the recovery process. Backup-job success does not prove recoverability.

SUPPORTING DISCIPLINES

Data, traffic & collaboration

OpenAPI, databases, transactions, caches, NGINX/HAProxy/Envoy, storage, messaging, ADRs, runbooks, ownership, onboarding, and FinOps.

Operational views. Combine RED (rate, errors, duration), USE (utilization, saturation, errors), and Golden Signals (latency, traffic, errors, saturation). Alert on sustained user impact with a clear owner, severity, threshold, and runbook.

05 / INTEGRATED ENGINEERING REFERENCES

Connected patterns. Explicit boundaries.

These examples connect the domains above. They are design and learning references, not claims of live deployment or production operation.

04
REF 01 / OBSERVABILITY

Local service signals

A Python HTTP API can expose liveness, readiness, and Prometheus metrics. Docker Compose can run the API with Prometheus and provisioned Grafana dashboards. Production adds secure ingress, authentication, durable storage, alert routing, retention, and SLO policy.

REF 02 / CLOUD NETWORK

Two-zone AWS topology

A VPC with public/private subnets across two Availability Zones, Internet Gateway routes, optional NAT egress, ECR, and optional EKS illustrates network separation. Costly resources should be opt-in; one NAT is not zone-resilient.

REF 03 / KUBERNETES

Hardened workload contract

Deployment, Service, startup/liveness/readiness probes, resource requests/limits, HPA, PDB, service account, seccomp, non-root execution, read-only root filesystem, and NetworkPolicy form a baseline. Metrics API and CNI support must be verified.

REF 04 / SUPPLY CHAIN

Secure build and GitOps

A CI pipeline can test, build with Buildx, generate a CycloneDX SBOM, scan with Trivy, publish an immutable GHCR digest, and hand declarative Helm configuration to Argo CD for reconciliation.

REF 05 / PLATFORM

Backstage service catalog

Catalog entities and Scaffolder templates model service ownership and generate a consistent repository skeleton. Template source alone is not a running developer portal; integrations, permissions, and publication actions are required.

REF 06 / OPERATIONS

Measure, diagnose, recover

Combine RED/USE signals, traces, log context, release markers, runbooks, incident roles, and tested recovery procedures to connect system behaviour with user impact.
